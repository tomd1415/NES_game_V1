# What each gate proves — and what it does not

*Snapshot of `chore/linux-native-bootstrap-v63` at **2026-08-13**. Every row carries the
command that produces it, so you can re-run it rather than trust this page.*

The repeated failure on this branch has not been gates going red. It has been gates
being **green for the wrong reason** — an assertion that had never executed (F5), a
snapshot with no Python in it (F7), a guard satisfied by a comment (F14), a registry
with no guard at all (F15). Four separate instances in one week, each found only by
deliberately breaking the thing the gate claimed to watch.

So this page is not a list of tests. It is a list of **claims you may safely make
when each one is green**, and the claims you may not.

---

## The gates

| Gate | Green means | Green does **not** mean |
| --- | --- | --- |
| `node tools/builder-tests/run-all.mjs`<br>110 suites, ~25 min | The ROMs for the covered scenarios are byte-for-byte what they were, and the engine version constants agree | That the ROMs are *correct*. These are golden-hash comparisons; a wrong ROM frozen early stays green forever |
| `node scripts/snapshot-engine.mjs --check`<br>41 files | No engine source has changed or vanished relative to the v77 snapshot, checked in both directions (on disk, and in HEAD) | Anything about `tools/playground_server.py`, which is **outside** the snapshot. And nothing about v1–v75, which contain no Python at all |
| `pytest native/tests/contract/test_phase0_starter_fixtures.py` | The seven starter ROMs are unchanged since commit `aa12a75` | That they are right. **The baselines were generated by the code they check** — the manifest says so in `what_a_pass_means`. This gate catches drift, not error |
| `pytest native/tests/contract/test_validator_parity.py` | The native validators say exactly what the web's say — same ids, order, severities and message text — on the case corpus | That **every** declared problem id fires at least once, which is what the second test claims. (Until 2026-08-13 it enumerated ids by **regex over source**, so a validator whose id was written in single quotes needed no case at all — F17. Now parsed with `ast`, with a dynamic-id guard, and `mutate`'s `parity-coverage-blind-to-single-quotes` break reddens it.) Nor that a validator behaves correctly outside the corpus: `validate()` swallows a throwing check silently, so one that only throws on real projects loses its warning with no signal |
| `pytest native/tests/unit/test_pyside_import_guards.py` | Every test module still imports with PySide6 forced absent, so "Qt is missing" can never again look like a defect | Anything about whether those tests *pass* with Qt present |
| `pytest native/tests/contract/test_codegen_stays_snapshottable.py` | The five ROM-emitting entry points in `playground_server.py` are still one-line delegations into the snapshotted package, **and** that package is still in `INCLUDE_DIRS` | Anything about the *contents* of the snapshotted package. (Until 2026-08-13 the include half was decorative — a substring match over raw source that a comment naming the path satisfied, F14. It now matches string literals with comments stripped, and `mutate`'s `snapshot-include-list-removed` break reddens it.) |
| `pytest native/tests/unit/test_fixtures_are_tracked.py` | The fixture ROMs are in the index, so a fresh clone gets them and the ROM assertion actually executes | — |

## What has no gate at all

* **`MODE_CLASSES`** (F15). A mode written but not registered is silently absent from
  the app. Nothing references the registry in any test.
* **`project_catalog.STARTERS`** (F16). The pupil-facing starter picker is a
  hand-copied list whose comment says "Keys must match the manifest", and nothing
  checks that they do. A starter shipped but not listed cannot be opened by anyone —
  the exact bug that module was written to fix. `StarterCatalog.styles()` exists to
  make this self-maintaining and has zero callers.
* **The whole Qt UI layer.** Without PySide6 the suite reports **215 passed, 161
  skipped** (204 before this week's new tests). The run reports more outcomes than
  `pytest --collect-only` counts, because whole modules skip at import — that gap is not
  an error. Skipped is *not* passing: this is now the largest uncovered surface on the
  branch, and stays that way until the container is rebuilt.
* ~~**The Studio E2E suite.** `npx playwright test` has never executed in this container.~~
  **Ran 2026-08-13: 129 passed, 0 failed, 6.2 min**, and **watched fail** — see below.
  Two caveats remain: it needs `PLAYWRIGHT_CHROMIUM_PATH` pointing at an apt-installed
  Chromium until the container is rebuilt (a *different* build from the one this
  Playwright was tested against), and the count is 18 short of `main`'s 147 because three
  spec files main added do not exist here.
* **Starter *content*.** `targetEngine: 63` pins the engine version stamp; it does not
  pin what the starter projects contain, so a fixture claiming "engine v63" is only
  half-pinned.

## Which of these has been watched fail

A gate nobody has seen go red is a claim, not a check. The probe is always: mutate the
guarded thing, run the gate, restore, **verify the restore by hash**. Eighteen probes
were run on 2026-08-09 (eleven on the starter-fixture gate, three on the parity
coverage check, four on the PySide6 guard), on top of those recorded on 2026-08-08.

**Broken on purpose and confirmed red:** the starter ROM hash comparison (one byte
flipped), the fixture-tracked guard, both directions of the snapshot check, the
delegation half of the codegen guard (a statement inlined), the PySide6 import guard
(a guard removed), the baseline manifest's `known_gaps` rule, the icon size three-way
agreement (one installer loop shortened — the case a union check could not catch), and
**every one of the eleven assertions in the starter-fixture gate**, including the
caveat text itself, which fails when reworded to claim correctness rather than merely
when deleted.

**Broken on purpose and stayed green:** the include-list half of the codegen guard (F14)
and the parity suite's coverage check (F17) — both regexes over raw source, both fooled in
the safe-looking direction. Both are now fixed, and both breaks are in the mutation spec so
neither can come back quietly.

> **This section briefly claimed F17 was fixed when it was not.** I fixed F14 while
> mutation-testing, only ever *described* F17's fix, and then wrote "both are now fixed"
> from memory while refreshing this page — in the document whose entire purpose is to stop
> a claim being made without the check being run. Caught by planting the break: it stayed
> green. Fixed for real on 2026-08-13, and the break now reddens it. **The page's own rule
> applies to the page: re-run it, do not remember it.**

**Now proved by tool rather than by hand.** `mutate tests/mutations/guards.json` runs **15**
breaks, each naming the assertion it must redden, and fails if a named assertion stays
green, if nothing fails anywhere, or if the anchor matched zero or more than one time. It
caught F14 on its first run — a guard I had hand-proved two days earlier. Hand-probing is
six steps with no feedback when one is skipped; this is the tooling that replaces it.

**The Studio E2E suite can fail, and precisely.** A green run from a suite nobody had
ever executed here is exactly the claim this page exists to distrust, so it was probed:
changing the promo banner's wording in `studio-promo.js` from "Early testing build" to
"Early preview release" reddened `promo.spec.js:9`'s
`toContainText('testing build')` — the named assertion, naming the expected substring —
while the file's *other* test stayed green. Restored, hash-verified identical, green
again. One targeted break is not a mutation sweep of all 28 spec files, and that is
stated rather than implied.

**Green by design, and correctly so:** `test_no_test_module_needs_pyside6_to_be_imported`
passes vacuously if the module walk finds nothing or a module fails to import. Its two
sibling assertions exist for exactly that and both went red when probed. This is the
only gate in the repo that already had a meta-test, and it holds.

**Still never watched fail:** the 110 builder suites. Five of `test_baseline_manifest`'s
six assertions are now probed by the mutation spec — it was named here as the last
unprobed gate and no longer is. Everything on this page has been probed at the
**assertion** level rather than the file level, which is the distinction that produced
F14 and then F17; the builder suites have had no equivalent, which is why that is the
next thing worth doing.

## Two things that look like signals and are not

* **`ppid=1` on a `playground_server.py`** does not mean a leaked server. The
  container's own dev server on 8765 is started by `start.sh` at boot and is orphaned
  to init permanently. Check the port range — the runner allocates **18800–19129** — not the parent.
* **`git check-ignore` reporting nothing** does not mean a path is un-ignored. It is
  index-aware and never reports a tracked file, so it cannot be used to prove an
  ignore rule is harmless. Probe with an untracked file instead.
